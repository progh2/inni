## 1. 조사 범위

읽은 출처:

- 라우트: `app/Router.php` (`public/index.php`의 `?r=` 디스패치)
- 컨트롤러: `app/Controllers/*.php` (14개)
- 도메인: `app/{Auth,Loan,Stock,Inventory,Catalog,CatalogCsv,Asset,AssetBoard,AssetLife,AssetLifeBoard,MaterialBoard,Budget,Alert,Scan,PpsUsefulLife}.php`
- 뷰: `templates/` (레이아웃·홈·찾기·스캔·실·품목·장비·재료·대여·라벨·실사·CSV·설정)
- 스키마: `sql/schema.sql` (+ `app/Database.php` 마이그레이션이 같은 컬럼을 맞춤)
- 기획 대조: `docs/PRD.md`, `docs/ERD.md`, `docs/STATUS.md`, README

역할 코드는 `users.role`의 `owner` / `manager` / `teacher` / `student` 네 가지다. 이해관계자 네 직군과 **1:1로 매핑되지 않는다.**

| 이해관계자 | 현재 역할로 할 수 있는 일 | 비고 |
|------------|---------------------------|------|
| 학교 기자재 담당자 | `owner`·`manager` (`canWrite`, `canInventory`) | 장비·실·실사·라벨·CSV의 쓰기 주체 |
| 실험실습재료 담당자 | 위와 **동일 권한** | 재료 전용 역할·메뉴 없음. 품목 상세에서 입고/출고 |
| 교사 / 실습실무사 | `teacher` (`canLoan`, `canReturn`) | 실무사 전용 역할·데스크 화면 없음. 학생(`student`)은 쓰기 차단, 본인 반납만 |
| 예산 담당자 | `owner`·`manager`와 **동일** | 예산 전용 역할·합계·처리 화면 없음 |

`manager`는 학교명·사용자 승인을 빼고 `owner`와 쓰기가 같다. 교사에게도 사이드바 **빠른 등록**이 보이지만 `items/save`는 `canWrite`에서 거절된다.

### 2.3 하단 탭·더보기 (현재 IA)

모바일 탭: **홈 / 찾기 / 스캔 / 실 / 더보기**. PC는 좌측 동일.

더보기: 품목 목록, 기자재 현황, 연한·노후 기자재, 실험실습재료 현황, 빠른 등록, 대여 현황, 라벨, (담당) 실사·CSV·학교 설정, (owner) 사용자 승인, (AI 키 있을 때) AI 자리.

교사 전용 탭(내 대여함·수리함·분출함)은 없다.

## 3. 이해관계자별 필요 기능 vs 현재

| 고장·수리 요청 | 부분 | 장비 상세 폼 (제목·내용·사진) | `open` 고정. 접수/수리중/완료 없음. 홈의 “신고 N”은 숫자만 → M5 #46 |
| 실(시설) 고장 신고 | 없음 | 스키마 `target_type=room`, 실 상세는 목록만 | 작성 폼 없음 |
| 재료 분출 (수업) | 부분 | 품목 상세 출고 | 찾기/재료 보드에서 바로 분출·실 지정 없음 → M6 #49 |
| 실 사용·배치 확인 | 부분 | 실 탭으로 목록 열람 | 실 예약·사용 체크인·담당 실 바로가기 없음 |

| 학생 내 대여 | 없음 | 역할만 존재 | PRD Phase 3. 이번 M5–M8 밖 |

**판정:** 교사·실무사는 **조회는 넓고 행동은 상세 페이지에 숨겨져 있다.** P0 대여 엔진은 있으나 “오늘 내가 빌린 것 / 창구에서 3탭”이 없다. M5가 가장 얇은 UX 갭이다.

### 3.4 예산 담당자 — 사업예산·구입년도·재물조사·내용연한·노후·보정·파기·수리비

| 필요 기능/화면 | 상태 | 현재 | 갭 |
|----------------|:----:|------|-----|
| 사업명·예산연도 기록 | 있음 | 품목/장비 필드, 자유 입력 | 학교별 사업 프리셋 없음 (의도적) |

## 4. 교차 갭 (역할·상태·용어)

1. **직군 ≠ 역할.** 재료 담당과 예산 담당을 `manager`에 얹으면 메뉴가 기자재 중심(실사·라벨·CSV)으로 보인다. 새 역할보다 **역할별 홈/더보기 카드**가 M8에 더 싸게 맞는다.
2. **상태 머신이 대여만 돈다.** PRD의 수리중·분실·폐기예정은 필터용이다. 고장 신고와 자산 상태가 끊겨 있다.
3. **스캔은 조회다.** 대여·반납·분출·실사 확인이 각각 다른 POST다. 실무사 데스크·재료 분출은 스캔 결과를 액션으로 이어야 한다.
4. **용어.** 코드/UI는 “사용 출고”, 현장은 “분출”. 실사는 가벼운 확인이지 재물조사 리포트가 아니다. M5–M7 화면 카피는 학교말로 맞출 것.
5. **교사에게 쓰기 버튼이 보인다.** 빠른 등록·(권한 없는) 실사 링크는 숨기거나 설명해야 한다 (M8).
6. **AI·에듀파인·학생 앱**은 자리만 있거나 후순위. 네 직군 핵심 경로를 막지 않는다.

## 5. 우선순위 제안

구현하지 않고 **순서만** 고정한다. 이미 열린 이슈(#45–#55)와 맞춘다.

```
M4 갭감사 (이 문서)  →  M5 교사·실무사 대여반납수리
                    →  M6 재료분출·재고
                    →  M7 예산·재물조사·연한·노후·파기·보정
                    →  M8 다듬기·교사UX
```

| 단계 | 목표 | 왜 이 순서 | 이슈 | 의존 |
|------|------|------------|------|------|
| **M4** | 역할별 있음/부분/없음 합의 | 구현 전에 화면 목록을 고정 | 이 문서 (#44) | — |
| **M5** | 교사·실무사가 폰으로 대여·반납·수리 요청 | 일일 트래픽이 가장 큼. 기존 `loans`·`reports`·스캔을 재사용 | #45 내 대여함 · #46 수리 상태 · #47 대여 데스크 | 스키마 소폭(신고 상태, 대여 필터) |
| **M6** | 재료 담당·교사의 분출·재고 | 출고 엔진은 있음. 실 지정·보드 CTA·로트 필드가 남음 | #48 등록·로트 · #49 분출 · #50 재료 보드 | M5 스캔 CTA와 맞추면 좋음 |
| **M7** | 예산·재물조사·연한·노후·파기·보정·수리비 | 필드(#32 #39 #40)와 가벼운 실사(#10) 위에 리포트·파괴적 쓰기 | #51 실사×예산 · #52 노후 보드 · #53 보정·파기 · #54 수리비 | #54는 #46 수리 건이 있어야 의미가 있음 |
| **M8** | 초임·노련 교사 UX | 핵심 화면이 생긴 뒤 용어·첫 탭·숨길 버튼 | #55 피드백 루프 | M5 화면 이후 |

M5를 M7보다 앞에 두는 이유: 수리 요청이 있어야 수리비가 붙고, 대여 상태가 깨끗해야 실사 차이가 해석된다. M6를 M7보다 앞에 두는 이유: 재물조사 수량 보정은 재료 로트 모델이 안정된 뒤가 안전하다.

**M5에서 하지 말 것:** 파기, 감가상각, 에듀파인 임포트, 학생 앱, 라벨 템플릿 편집기, 키트 BOM.

**M7에서 하지 말 것:** 에듀파인 **대체** 회계. 보조 대장·파일 동기화만 (PRD §6.13).

## 7. P0–P3와의 관계

닫힌 이슈는 **인프라·대장·보드**에 가깝고, 열린 M5–M8은 **직군 워크플로**다.

| 구간 | 닫힌 이슈 (요지) | 네 직군에 남은 것 |
|------|------------------|-------------------|
| P0 | CSRF, owner 부트스트랩, 대여 동시성, 역할 차단, Docker, OAuth, 스캔·라벨 | 스캔이 조회에서 끝남 |
| P1 | 수정·입고·출고취소, 가벼운 실사, CSV, 알림, AI 자리 | 실사는 확인만. AI는 설정 상태만 |
| P2 | 품목 목록, 기자재 보드, 더보기, 사업예산 | 예산 리포트·실사 연동 없음 |
| P3 | 재료 보드, 도입일·연한, 조달청 제안 | 노후 처리·파기 없음 |
