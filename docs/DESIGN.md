# inni v2 설계 노트 — "무엇을 가장 자주 하는가"에서 출발

> 2026-09-30 · v2(보급 함교) 재구성 때 정한 설계 원칙과 그 이유를 적는다.
> 기능 목록은 [README](../README.md), 운영은 [NAS 배포](nas-deploy.md)·[Firebase](firebase-setup.md)·[백업·이전](backup-restore.md)을 본다.

## 1. 누가, 어디서, 무엇을 하는가

| 사람 | 주로 있는 곳 | 가장 자주 하는 일 | 가끔 하는 일 |
|------|--------------|-------------------|--------------|
| **일반 교사** | 실습실·복도, **휴대폰** | "그거 어디 있지?" 찾기 · 빌려 가기 · 반납 | 고장 신고 |
| **담당교사**(기자재 담당) | 준비실 PC + 휴대폰 | 옮기기 · 빌려주기/반납 받기 · 소모품 쓰기/입고 · 새 물건 등록 | 실사 · 수리 처리 · 보고서 · 라벨 인쇄 |
| **관리자**(정보 담당) | PC | 사용자 승인 · 설정 | 백업 · 이전 · AI 연결 |
| **학생**(선택) | 휴대폰 | 찾기 · 고장 신고 | — |

빈도로 줄 세우면 **찾기 ≫ 옮기기·빌려주기·반납·사용 ≫ 등록 ≫ 실사·수리·보고**다.
그리고 거의 모든 작업이 **손에 물건을 든 채, 서서, 휴대폰으로** 일어난다. 그래서 설계는 이 순서를 따른다.

1. **찾기는 0단계** — 어느 화면에서든 곧바로 입력(또는 말)할 수 있어야 한다.
2. **자주 하는 네 가지(옮기기·빌려주기·반납·사용)는 한 번 누르기** — 확인 창 대신 **되돌리기**.
3. **등록은 사진 한 장부터** — 타자를 최소화하고 나머지는 추정·기본값으로.
4. **가끔 하는 일은 PC에서 넓게** — 실사·보고서·설정은 넓은 화면을 전제로 한다.

## 2. 지금까지(v1)의 불편과 v2의 답

v1(PHP)은 기능이 많았지만 "화면이 곧 메뉴"였다. 현장에서 걸리는 점은 이랬다.

| 불편 | 원인 | v2의 답 |
|------|------|---------|
| 찾으려면 메뉴부터 고른다 | 목록 화면이 기능별로 나뉨 | 맨 위 **한 칸 검색**(이름·초성·관리번호·장소·QR·말). `/` 키, 휴대폰 하단 탭 |
| 이름을 정확히 몰라서 못 찾는다 | 부분 일치만 | **초성**(ㅁㅌㅁㅌ)·**오타 허용**·**별칭**·**장소 섞어 찾기**("공구실 드릴") |
| 옮기거나 빌려주는 데 여러 화면 | 폼 중심 | 물건 화면의 **큰 버튼** → 한 장의 시트 → 끝. 최근 장소·최근 빌린 사람을 먼저 보여 줌 |
| 실수할까 봐 확인 창이 많다 | 되돌리기 없음 | 모든 변경을 **기록(event)** 에 되돌릴 정보와 함께 저장 → 알림의 **[되돌리기]** (본인 30분, 담당교사 7일) |
| 등록이 귀찮아 대장이 비어 간다 | 칸이 많음 | **사진 → AI가 이름·종류·제조사 초안**, 제품 링크 붙이면 자동 채움, 같은 물건이면 **"여기에 더하기"** |
| 라벨이 있어도 앱을 열어야 한다 | 앱 전용 스캐너 | QR에 `주소/q/코드` → **휴대폰 기본 카메라**로 찍어도 그 물건이 열린다. USB 바코드 스캐너도 그냥 인식 |
| 다른 사람이 옮긴 걸 모른다 | 새로고침 필요 | **실시간 알림(SSE)** — 아래 통신 띠(COMMS)와 3D 지도에 바로 뜸 |
| 설치·백업이 어렵다 | PHP·Apache·설정 파일 | **컨테이너 1개 + `data` 폴더 1개**. 백업은 **zip 한 파일** |

## 3. 설계 원칙

### 원칙 1. 어디서든 찾는다 (검색은 기능이 아니라 바닥)
- 상단 옴니박스와 휴대폰 **찾기 탭**은 모든 화면에 있다. `Ctrl+K` 명령 팔레트는 화면·명령·물건을 한 번에 찾는다.
- 결과의 첫 줄은 항상 **"어디에"** — 사람이 알고 싶은 건 물건 정보가 아니라 위치다.
- 검색 색인은 서버 메모리의 스냅샷이라 입력하는 동안 바로 바뀐다. 측정(품목 3,000 · 장비 6,000 · 장소 64): 찾기 1~10ms, 스냅샷 다시 만들기 약 70ms.
- 말로도 찾는다: 🎤 → "멀티미터 어디 있어?" → 규칙 해석(AI 없이도) → 결과 화면.

### 원칙 2. 한 번 누르고, 틀리면 되돌린다
- 옮기기·빌려주기·반납·사용·입고는 **시트 한 장**. 필수 칸만 있고 나머지는 기본값(오늘 수업 끝, 최근 장소…).
- 실행 즉시 반영하고 **되돌리기 토스트**를 띄운다. 확인 창은 **파기·삭제·복원**처럼 되돌리기 어려운 일에만.
- 되돌리기는 "반대 작업을 새로 기록"하는 방식이라 기록이 지워지지 않는다.

### 원칙 3. 입력은 사람이 아닌 기계가
- 사진 한 장 → (AI 연결 시) 이름·종류·분류·제조사·모델·규격·별칭 초안과 **확신도**. 사람은 고치기만.
- 제품 링크 → 쇼핑몰 페이지의 OG/JSON-LD를 읽고, AI가 있으면 규격까지 정리.
- 이름 → 네이버·카카오 검색 API(키가 있으면)로 **제품 사진 후보**. 없으면 검색 사이트 바로가기.
- 배경 지우기·자르기·밝기는 브라우저 편집기에서. 무거운 AI 배경 제거는 선택(브라우저 모델 또는 rembg 컨테이너).
- 관리번호는 "앞머리 + 연도 + 순번"을 자동으로 이어 붙인다. 내용연수는 **조달청 고시** 표에서 제안(강제 아님).

### 원칙 4. AI는 제안하고, 사람이 누른다
- 이니(AI 보급관)는 **읽기 도구**(찾기·장소 내용·대여·경보)와 **제안 도구**(옮기기·빌려주기·반납·사용·입고·고장 신고 초안)만 가진다.
- 제안 도구는 서버에서 **실제 대상과 요청 본문을 미리 확정**해 "카드"로 보여 줄 뿐이다. 카드의 버튼을 사람이 눌러야 **기존 API**가 불리고, 권한·검증·기록·되돌리기는 손으로 할 때와 똑같다(기록에 `이니` 표시).
- 역할별로 도구 자체를 뺀다(학생에게는 옮기기 도구가 없다). 헷갈리면 되묻는다("충전드릴이 2가지예요").
- 학교 밖 모델(OpenAI 등)에는 **사람 이름을 가명으로 바꿔** 보내고 답에서 되돌린다. 월 토큰 상한이 있다.
- AI가 없어도 이니는 **규칙 명령**으로 동작한다("드릴 2대 공구실로 옮겨 줘", "실납 3롤 썼어"). AI는 편의이지 전제가 아니다.

### 원칙 5. 함교 연출은 "정보"여야 한다
공상과학 연출(aiapi 관제 함교 계열)은 재미를 주지만, 모든 효과는 실제 정보를 나른다.

| 연출 | 뜻 |
|------|----|
| **CONDITION GREEN/YELLOW/RED** | 지금 경보(연체·급한 고장·재고 부족…)의 최고 수준과 개수 |
| **3D 선내 지도(DECK MAP)** | 건물=덱, 실=구획. 도면을 올린 건물은 **층을 쌓고 실제 실 모양**으로. 경보가 있는 실은 붉게, 찾는 물건이 있는 층만 또렷하게 하고 그 실엔 **비콘** |
| **COMMS 띠** | 방금 누가 무엇을 했는지(실시간) |
| **이니의 표정** | 치비 보급관 견습생(ChatGPT 이미지 모델로 그린 9장). 성공(기쁨·손 흔들기)·경보(땀방울)·오류(><)·생각(턱에 손)·듣기(귀에 손)·쉬기(AI 꺼짐) |
| **효과음** | 성공/경고/스캔 인식. `M`으로 끄기 |

- `prefers-reduced-motion`이면 움직임을 줄이고, 3D는 `T`로 끌 수 있다(저사양 PC·태블릿).
- 휴대폰에서는 3D·말풍선을 줄이고 **하단 탭(함교·찾기·스캔·입출항·메뉴)** 중심으로 바뀐다.
- 준비실 모니터용 **상황판 모드**(`A`)는 함교·장소·입출항·정비 화면을 차례로 돌려 보여 준다(누가 만지면 30초 쉼).

### 원칙 6. 운영은 선생님 한 명이 감당할 수 있게
- NAS에 **컨테이너 1개**. DB(SQLite)·사진·백업이 전부 `./data` 한 폴더.
- 백업은 **zip 한 파일**(DB 스냅샷 + 사진 + 설명서). 매일 자동 백업·보관 개수 설정.
- 이전은 "새 NAS에 설치 → 로그인 → zip 복원" 세 단계. 스키마가 올라가면 복원 때 자동 이행.
- 예전 inni(PHP)의 DB를 넣으면 **아이디와 QR 값을 그대로** 가져와서, 이미 붙인 라벨이 계속 통한다.

## 4. 구조

```
브라우저(휴대폰·태블릿·PC)                       NAS 도커 컨테이너 (Node 22)
┌──────────────────────────────┐   HTTPS   ┌───────────────────────────────────────┐
│ web/  빌드 없는 ES 모듈 SPA    │ ────────▶ │ server/  Express 5                     │
│  · 스테이션 10개(해시 라우팅)   │   SSE     │  · 세션 쿠키(HttpOnly) · CSRF 머리글   │
│  · three.js 선내 지도          │ ◀──────── │  · 권한 표(역할 × 능력)                │
│  · 이미지 편집기(canvas)       │           │  · 스냅샷 검색(초성·오타·장소)          │
│  · 음성(Web Speech)            │           │  · 작업 = 트랜잭션 + 기록(되돌리기)     │
│  · Firebase Auth(로그인만)     │           │  · AI 엔진(도구 호출·제안 카드·가명)    │
└──────────────────────────────┘           │  · 백업 zip · CSV · 예전 DB 가져오기    │
        │ ID 토큰 1회                        │  better-sqlite3 (WAL)  ./data/inni.db │
        ▼                                    └───────────────────────────────────────┘
   Firebase Auth (구글 / 메일 링크)                  │ (선택) OpenAI · Ollama · aiapi-manager
                                                      │ (선택) 네이버·카카오 검색 · rembg
```

- **Firebase는 신원 확인에만** 쓴다. 로그인 때 받은 ID 토큰을 서버가 구글 공개키로 직접 검증(서명·aud·iss·만료)하고, 그다음부터는 이 서버의 세션 쿠키만 쓴다. 데이터는 학교 NAS를 떠나지 않는다.
- 역할: 관리자(owner) · 담당교사(manager) · 교사(teacher) · 학생(student). 능력(cap) 단위로 나눠 두고, "교사도 등록 가능" 같은 학교 정책은 설정으로 켜고 끈다.
- 모든 쓰기는 즉시 모드 트랜잭션 + 기록 한 줄. 기록에는 되돌리기 정보가 같이 들어간다.

### 데이터 모델(요약)

| 표 | 뜻 |
|----|----|
| `items` | 품목(같은 규격의 물건). 종류: 장비·비품·소모품·부품 |
| `assets` | 장비 한 대 한 대(관리번호·시리얼·상태·위치·QR). 화면에서는 "장비" |
| `stocks` | 비품·소모품의 **장소별 수량**(로트·유통기한) |
| `locations` | 장소 트리(건물 › 실 › 선반/칸), QR |
| `loans` | 대여(누가·언제까지·반납) |
| `events` | 모든 변경 기록 + 되돌리기 정보 + `via`(손/이니/스캔) |
| `repairs` | 고장 신고 → 처리 → 완료, 비용 |
| `audits` / `audit_lines` | 실사(장소별 예상 목록·확인·미확인·보정) |
| `categories` | 분류 |
| `users` / `sessions` | 승무원·세션(토큰은 해시로만) |
| `settings` / `secrets` | 학교 설정 / API 키(화면에는 끝 네 자리만) |
| `floor_plans` | 층(또는 단층 건물)마다 도면 그림 한 장 + 그 위에 그린 실 모양(다각형, 그림 픽셀 좌표) + 현관·계단·승강기 표시 + 축척 |

## 5. 일부러 하지 않은 것

- **오프라인 쓰기** — 학교 Wi-Fi가 끊기면 저장이 안 된다고 분명히 보여 준다. 두 기기의 오프라인 수정을 합치는 복잡도를 피했다.
- **Firestore 등 클라우드 DB** — 학교 자산 대장은 학교 NAS에. Firebase는 로그인만.
- **AI의 직접 실행** — 편해 보여도 잘못 알아들으면 대장이 틀어진다. 카드 한 번 누르기의 비용이 훨씬 싸다.
- **멀티 학교(테넌트)** — 학교마다 자기 NAS에 하나씩. 코드만 같이 쓴다.
- **에듀파인 직접 연동** — 관리번호 칸과 CSV로 맞춘다.

## 6. 열린 질문(다음에 정할 것)

- 학생 로그인을 기본으로 켤지(지금은 꺼짐, 설정에서 켬).
- 라벨 규격 표준화(학교에서 쓰는 라벨지 목록을 받아 프리셋 추가).
- 실사 주기 알림(학기 초·말)과 보고서 양식.
- 대여 데스크의 "학생증 바코드" 연동(학번 → 사람).
