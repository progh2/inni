# 백업 · 복원 · 이전

inni의 모든 데이터는 **`data` 폴더 하나**에 있다.

```
data/
├── inni.db (+ -wal, -shm)   데이터베이스(물품·장소·대여·기록·사용자·설정·API 키)
├── uploads/                  사진(원본·썸네일)
└── backups/                  백업 zip (자동·직접·복원 전)
```

백업 파일은 **zip 한 개**다.

```
inni-backup-20260930-221258-auto.zip
├── manifest.json     만든 시각·학교·버전·개수
├── inni.db           데이터베이스 스냅샷(로그인 세션은 뺌)
├── uploads/…         사진
└── 읽어보세요.txt
```

> ⚠ 백업에는 **설정의 API 키**(AI·검색·텔레그램)가 들어 있다. 학교 밖 클라우드에 올릴 때는 주의한다.

---

## 1. 백업

### 자동 백업(기본 켜짐)
시스템(09) → **백업·이전** → "매일 자동 백업", 시각(기본 03시), 남길 개수(기본 14개).
- 자동 백업은 남길 개수만큼만 두고 오래된 것부터 지운다. **직접 만든 백업은 지우지 않는다.**
- 텔레그램을 켜 두면 성공/실패를 알려 준다.

### 직접 백업
같은 화면의 **[지금 백업]** → 목록의 ⬇로 내려받기. 큰 정리 전에 한 번.

### 업데이트 전 자동 백업
NAS 자동 업데이트([nas-deploy.md §7-2](nas-deploy.md#7-2-자동-업데이트-권장-aiapi-manager와-같은-방식))는 새 버전을 받기 직전에
`…-before-update.zip`을 남긴다(최근 5개). 손으로는 `docker compose exec -T inni node server/cli.js backup --reason before-update`.

### NAS 쪽에서 한 번 더(권장)
NAS가 고장 나면 NAS 안의 백업도 같이 사라진다. `data/backups` 폴더(또는 inni 폴더 전체)를 다른 곳에 복사해 둔다.
- 시놀로지: **Hyper Backup**으로 `docker/inni/data/backups`를 USB·다른 NAS·C2로. 또는 **Cloud Sync**로 학교 드라이브에.
- 그냥 폴더를 복사해도 된다. `inni.db`를 직접 복사할 때는 컨테이너를 멈춘 뒤(`docker compose stop`)에 한다(zip 백업은 켠 채로 안전).

## 2. 복원

시스템(09) → 백업·이전 → **[백업 파일로 복원…]** → zip 고르기 → "복원" 입력.

1. 지금 상태를 **복원 전 백업**(`…-before-restore.zip`)으로 먼저 남긴다(최근 5개 보관).
2. DB와 사진을 통째로 바꿔 끼운다. 더 옛날 버전의 백업이면 새 구조로 자동으로 옮긴다.
3. 모든 사람이 **다시 로그인**한다.

- 목록에 있는 백업은 옆의 **[복원]** 으로 바로 된다.
- 파일이 커서 브라우저로 올리기 어렵다면: zip을 **이름 그대로** `data/backups/`에 복사(File Station) → 화면을 새로 고치면 목록에 뜬다 → [복원].
  (컨테이너가 만든 폴더라 권한 때문에 복사가 막히면 SSH에서 `sudo cp`를 쓰거나 브라우저로 올린다.)
- 더 새 버전의 inni에서 만든 백업은 거절한다 → 프로그램을 먼저 업데이트.
- 잘못 복원했으면 `…-before-restore.zip`을 다시 복원하면 된다.

## 3. 다른 NAS·PC로 옮기기

### 방법 A — 백업 zip (권장)
1. **예전 곳**: 시스템 → 백업·이전 → [지금 백업] → 내려받기.
2. **새 곳**: inni 설치([nas-deploy.md](nas-deploy.md)) → `.env`는 예전 것을 복사(같은 Firebase 프로젝트면 그대로).
3. 관리자로 로그인 → 처음 설정 화면의 **[백업 파일로 복원]** (또는 시스템 → 백업·이전) → zip.
4. 주소가 바뀌었으면: `.env`의 `PUBLIC_URL` 수정, Firebase **승인된 도메인**에 새 주소 추가.
   라벨 QR은 `주소/q/코드` 모양이라 **주소가 바뀌면 예전 라벨을 기본 카메라로 찍었을 때 옛 주소로 간다.** 앱 안 스캐너(코드만 읽음)는 계속 된다. 가능하면 같은 도메인을 새 NAS로 옮긴다.

### 방법 B — 폴더 통째로
1. 예전 곳에서 `docker compose stop`
2. inni 폴더 전체(특히 `data/`와 `.env`)를 새 곳으로 복사
3. 새 곳에서 `docker compose up -d --build`

## 4. 예전 inni(PHP)에서 옮기기

v1(PHP·SQLite) 데이터를 **아이디와 QR 값을 그대로** 가져온다. 이미 붙여 둔 라벨이 계속 통한다.

1. 예전 DB `data/inni.sqlite`를 새 inni의 `data/` 에 둔다(같은 폴더에 설치했다면 이미 있다).
2. 예전 사진 `public/uploads/*`를 새 inni의 `data/legacy-uploads/`로 복사한다.
   (도커가 아니라 같은 폴더에서 직접 실행하면 `public/uploads`를 알아서 찾는다.)
3. 새 inni에 **물품이 하나도 없는 상태**에서 관리자로 로그인 → 처음 설정 화면의 **[예전 inni 데이터 가져오기]**.
   - 무엇이 몇 개 있는지 먼저 보여 준다. 예전 데모 계정(`demo-owner` 등)은 기본으로 빼고 가져온다.
   - 가져오는 것: 사용자·장소·분류·품목·장비·재고·대여·고장 신고(수리비 포함)·활동 기록.
4. 다른 경로에 있으면 `.env`에 `LEGACY_DB=/app/data/old.sqlite`, `LEGACY_UPLOADS=/app/data/old-uploads`.

> 섞이지 않도록 **빈 inni에서만** 가져온다. 다시 하고 싶으면 `data/inni.db`를 지우고(먼저 백업!) 컨테이너를 다시 시작한다.

## 5. 엑셀(CSV)로 주고받기

시스템(09) → 백업·이전 → **엑셀(CSV)로 한꺼번에**

- **[양식]** 을 받아 채우고 **CSV UTF-8**(또는 엑셀 기본 CSV — CP949도 읽는다)로 저장 → **[CSV 가져오기]**.
- 먼저 **미리보기**로 새로 만들 것·고칠 것·건너뛸 것(이유와 함께)을 보여 준다. 확인해야 반영된다.
- **품명+종류**가 같은 줄은 한 품목으로 묶는다. 장비는 한 줄에 한 대(관리번호) 또는 수량만큼. **이미 있는 관리번호**는 건너뛰어 두 번 들어가지 않는다.
- 위치는 `실습동 › 공구실`처럼 적거나 실 이름만 적는다. 없는 장소는 새로 만든다(미리보기에 목록이 나온다).
- **[지금 물품 내보내기]** 는 지금 대장을 CSV로. 기록(07) 화면에서 작업 기록 CSV, 정비(06)에서 수리비 CSV도 받을 수 있다.
